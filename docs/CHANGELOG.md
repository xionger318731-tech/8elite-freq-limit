# 8elite 限频 · 更新日志

## V1.3　（2026-10-27）　作者：罗霄山

### 算法（自研，核心重构）
旧版（V1.2fix）控制律 `cap = 读回节点 × (负载/目标)²` 是**无绝对锚点的乘性随机游走**，且把 sysfs 节点当迭代基准、会被 ColorOS `oiface` 抢写污染；升档零滤波、单 tick 最大 3×，两个 tick 就放弃限频；CPU 使用率判据在负载侧饱和，区分不出"需要 2G"和"需要 3.5G"。

新版采用**双判据容积伺服（DCS，Dual-Criterion Servo）**：

- **需求密度前馈**　`need = 忙时平均频率 × 利用率 / 目标占用` —— cap-invariant 的绝对量判据，不再随基准漂移；
- **撞顶率伺服**　`cap = need × (1 + K·(撞顶率 − 死区))` —— 用"时间片里跑在多靠近天花板的比例"作为**不饱和判据**，取代已饱和的 CPU 使用率；
- **整机功耗外环**　自动在 35–75 之间整定"目标占用"，消灭魔法常数，免机型重标；
- **内部权威 cap 副本**　节点值只用于对账，抗 `oiface` 抢写；
- **按包学习稳态 cap**　切应用秒回上次稳态，消除重收敛成本；
- **触摸 / 冷启动瞬时抬频**　替代旧版固定 15s 锁 2.4G 的浪费窗口。

### 借用 EtaTune 的感知输入（仅做限频输入，不引入其调度逻辑）
- 触摸协程（毫秒级感知：无触摸放心压、触摸瞬间抬）；
- 功耗读数口径 `|current_now| × voltage_now / 1e6`，含"充电时跳过"；
- WiFi / 数据双功耗预算。

> 边界说明：本模块**仍是纯限频模块**，不移植 EtaTune 的 cpuset 后台降级 / core_ctl 等调度策略——只是借它的"感知"让限频更聪明。

### 修复
- **严重 bug（误杀）**：旧版 daemon 从不写状态时间戳 `ts`，而 watchdog 用 `date +%s`（epoch）比对，导致**每 60 秒误判 daemon 卡死并杀掉重启**，限频持续抖动。V1.3 让 daemon 与 watchdog 统一改用 `/proc/uptime` 秒，彻底消除误杀。
- **状态全空**：旧版 WebUI / ctl 读 `eff_big`/`ratio_big`/`temp_big`/`style`，而 daemon 根本不写这些键，状态显示一片空。V1.3 重建 state 键（新增 `mode`/`style`/`need_big`/`ts` 等），ctl 与 WebUI 全部重对齐。
- 升/降档非对称确认、单 tick 限速、超大核双阈值迟滞、温度软增益等已内置。

### 兼容 / 卸载
- 卸载逻辑不变：cooling 归 0 = 内核"不干预"语义，实测零残留（沿用原审计结论）。
- 附带 `scripts/probe.sh`：上机前必跑，打印 cooling state→频率真表、time_in_state 可用性、功耗节点，用于校准 `map_*.conf`。

### ⚠ 已知待校准（上机第一件事）
`config/map_big.conf` 的 `state0 = 3072000` 与 `uninstall.sh` 注释声称的"state0 = 不干预"**互相矛盾**——二者必有一错。**上机先跑 `probe.sh`**，以实测 cooling 真表替换两个 map 文件；否则"释放"可能仍压 13–19%，所有省电收益都打折。
